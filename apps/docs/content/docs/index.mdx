`effect-state-machine` is a code-first state-machine library for TypeScript applications built
with Effect. A machine definition describes valid inputs, states, events, transitions, invoked
Effects, and child machines as one immutable value. The same value can be run by the interpreter
or projected into a read-only graph for development tooling.

The library is intended for Effect users who want orchestration to remain visible in ordinary
TypeScript. It assumes familiarity with `Effect`, `Schema`, `Layer`, and scoped resources.

## Installation

The current v0 release targets the Effect beta used to verify its semantics:

```sh
pnpm add effect-state-machine effect@4.0.0-beta.106
```

The package is ESM, targets ES2022, and exposes the main API from `effect-state-machine`. Static
graph tooling is also available from the opt-in `effect-state-machine/devtools` entry point.

## What v0 models

A machine node has one visible behavior kind:

- an ordinary state with pure transitions;
- an invoked Effect with typed success and failure routes;
- an invoked child machine with explicit event forwarding;
- a final state whose value becomes the machine completion value.

Machine instances serialize external events and asynchronous completions through one queue. Work
owned by an invoked or child state is interrupted when the machine leaves that state.

V0 does not provide parallel regions, dynamic actors, visual editing, durable execution,
persistence, replay, or application-framework bindings.
